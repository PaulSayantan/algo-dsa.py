# Solution — Approximate Matching (k Mismatches)

## Brute Force

Slide `P` over every window of `T` and count mismatches, stopping early once the
count exceeds `k`. There are `n - m + 1` windows and each costs up to `O(m)`,
giving `O(n * m)` per pattern. This is simple and fine for a single pattern over
a modest text, but in read alignment you align *millions* of patterns against one
big reference, so the recurring `O(n)` scan per read is prohibitive.

- Time: `O(n * m)` per pattern
- Space: `O(1)` beyond the inputs

## Optimal Approach (FM-Index + branching backward search)

Exact backward search follows exactly one character (the pattern's) at each step.
For approximate matching we let the search **branch**: at each pattern position we
may follow the matching character for free, or any *other* character at the cost
of one mismatch. Each root-to-leaf path of this search tree corresponds to a
string of length `m` that occurs in `T` (the interval stayed non-empty) and lies
within Hamming distance `k` of `P`. Summing the interval widths at the leaves
counts all such alignments.

### Steps

1. Build the FM-Index over `T` (`S = T + "$"`, `SA`, `BWT`, `C[]`, rank table),
   and record the alphabet excluding the sentinel.
2. Recurse over pattern positions `pos = m-1, m-2, ..., 0`, carrying the current
   interval `[sp, ep)` and remaining budget `b`:
   - For each alphabet character `c`:
     - `nsp = C[c] + Occ(c, sp)`, `nep = C[c] + Occ(c, ep)`.
     - If `nsp >= nep`, the extension `c...` does not occur — **prune**.
     - `nb = b - (0 if c == P[pos] else 1)`. If `nb < 0`, budget exhausted —
       **prune**.
     - Recurse on `(pos-1, nsp, nep, nb)`.
   - When `pos < 0`, the whole (approximate) pattern is matched: add `ep - sp` to
     the total.
3. Return the accumulated total.

```python
def count_k_mismatches(self, pattern, k):
    total = 0
    alphabet = self.alphabet   # excludes '$'
    m = len(pattern)

    def rec(pos, sp, ep, budget):
        nonlocal total
        if sp >= ep:
            return
        if pos < 0:
            total += ep - sp
            return
        for c in alphabet:
            nsp = self.C[c] + self._rank(c, sp)
            nep = self.C[c] + self._rank(c, ep)
            if nsp >= nep:
                continue
            nb = budget - (0 if c == pattern[pos] else 1)
            if nb < 0:
                continue
            rec(pos - 1, nsp, nep, nb)

    rec(m - 1, 0, self.n, k)
    return total
```

### Why it is correct

Fix any leaf reached by the recursion. Along the path we chose one character per
pattern position, forming a string `W` of length `m`; the interval stayed
non-empty, so `[sp, ep)` at the leaf is exactly the block of suffixes of `S`
beginning with `W`, i.e. `W` occurs `ep - sp` times in `T`. The number of
positions where our chosen `c` differed from `P` equals `k - nb`, which the
pruning guarantees is `<= k`. Conversely, every occurrence of every string within
Hamming distance `k` of `P` is generated by exactly one path (the one spelling
that occurrence's characters), so no alignment is double-counted and none is
missed. Adding leaf interval widths therefore counts precisely the alignments
within `k` mismatches.

### Complexity

- Build: `O(n)`–`O(n log n)` time, `O(n)` space.
- Query: the search tree has `O(m^k * sigma^k)` surviving branches in the worst
  case (choose which of `m` positions mismatch and which of `sigma` letters to
  put there), each costing `O(1)` rank work, so roughly
  `O(sigma * (m choose <=k) * sigma^k)` — polynomial in `m` for small fixed `k`,
  and vastly smaller in practice thanks to interval-emptiness pruning. Crucially,
  no term depends on `n` (only occurrence reporting would). This is why aligners
  can afford it per read.

## Key Insights & Edge Cases

- **Branch = mismatch.** Following the pattern's own character costs nothing;
  following any other charges one unit of budget. `k = 0` degenerates to exact
  count.
- **Two prunes** keep the tree small: empty interval (`nsp >= nep`) and negative
  budget (`nb < 0`). Both are essential; without interval pruning the tree would
  be `sigma^m`.
- **Counting vs. locating.** Adding `ep - sp` counts alignments. To *report*
  positions, collect `SA[i]` for `i` in each leaf interval (as in Problem 2) and
  deduplicate — different mismatch patterns can land on the same text position, so
  dedup by position if you want distinct start indices.
- **Fixed-length, Hamming only.** This counts equal-length windows. Allowing
  insertions/deletions (edit distance) needs an extra branch that consumes a
  pattern character without an interval step (and vice versa), turning it into the
  edit-distance backtracking used by full aligners.
- **Small alphabet matters.** The `sigma^k` factor is why FM-Index approximate
  matching shines on DNA (`sigma = 4`) but is used more carefully on large
  alphabets.
- **Sentinel excluded** from the alphabet loop, otherwise the search could
  "match" the terminator inside the pattern region.
