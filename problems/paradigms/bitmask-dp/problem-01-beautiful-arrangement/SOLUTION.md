# Beautiful Arrangement — Solution

## Brute Force

Generate every permutation of `1..n` and check the divisibility condition at
each position.

- **Time:** `O(n! * n)` — there are `n!` permutations and checking one costs
  `O(n)`. For `n = 15`, `15! ≈ 1.3 * 10^12`, far too slow.
- **Space:** `O(n)` for the recursion stack / current permutation.

A backtracking version that prunes as soon as a position violates the rule is
much faster in practice, but its worst-case bound is still factorial.

## Optimal Approach (Bitmask DP)

### Key observation

When we build the arrangement left to right, the only thing that matters for
future decisions is **which numbers have already been used** — not the order in
which we used them. That "set of used numbers" is a subset of `{1, ..., n}`,
which we encode as an integer `mask` where bit `(v - 1)` is set iff value `v`
is already placed.

Crucially, the position we are about to fill is determined by the mask:

```
position = popcount(mask) + 1
```

because filling positions in order means the k-th placement goes to position k.

### DP definition

Let `dp[mask]` = the number of ways to have placed exactly the numbers in
`mask` into the first `popcount(mask)` positions such that every filled
position so far is "beautiful."

- **Base case:** `dp[0] = 1` (empty placement, one way).
- **Transition:** for a mask with `pos = popcount(mask) + 1`, try every value
  `v` (bit `v-1`) that is **not** yet in the mask and that satisfies
  `v % pos == 0 or pos % v == 0`:

  ```
  dp[mask | (1 << (v - 1))] += dp[mask]
  ```

- **Answer:** `dp[(1 << n) - 1]` (all numbers placed).

### Why it is correct

Every beautiful arrangement corresponds to exactly one path of bit additions
from `mask = 0` to the full mask, and the transition rule only follows an edge
when the just-placed value is legal for its position. Because the next position
is fully determined by the popcount, we never double-count or skip an
arrangement: each permutation is generated by a unique sequence of "add the
value for position 1, then position 2, ..." steps.

### Reference implementation

```python
class Solution:
    def countArrangement(self, n: int) -> int:
        full = (1 << n) - 1
        dp = [0] * (1 << n)
        dp[0] = 1
        for mask in range(1 << n):
            if dp[mask] == 0:
                continue
            pos = bin(mask).count("1") + 1  # next position to fill
            if pos > n:
                continue
            for v in range(1, n + 1):
                bit = 1 << (v - 1)
                if mask & bit:
                    continue
                if v % pos == 0 or pos % v == 0:
                    dp[mask | bit] += dp[mask]
        return dp[full]
```

- **Time:** `O(2^n * n)` — one pass over all masks, `O(n)` work each.
- **Space:** `O(2^n)` for the DP array.

An equivalent formulation is top-down memoized recursion keyed on `mask`
(`@lru_cache`), which visits the same set of states.

## Key Insights & Edge Cases

- **Position is implicit in the mask.** You do *not* need to store the current
  position as a separate state coordinate; `popcount(mask)` gives it for free.
- **Iterating masks in increasing order** guarantees every source state
  `dp[mask]` is finalized before it is used, since adding a bit strictly
  increases the integer value.
- **`n = 1`** returns `1` (only `[1]`), handled naturally by the base case.
- **Pruning helps.** The `if dp[mask] == 0: continue` line skips unreachable
  states so you don't waste time on masks that no arrangement produces.
- **1-indexing.** The problem is 1-indexed; be careful mapping value `v` to bit
  `v - 1`.
